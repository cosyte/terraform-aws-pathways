# The alarms example

`examples/alarms` is the [minimal example](./example-minimal.md) with the module's alarms turned on.
[Turn on the alarms](./turn-on-the-alarms.md) explains each part.

## What it deploys

In an existing VPC, with a NAT gateway you already have:

- **One engine** on ECS Fargate, one vCPU and 2 GiB, as a service of one task, and beside it in the
  same task **a metrics collector** (AWS Distro for OpenTelemetry, by digest) that reads the
  engine's `/metrics` at 127.0.0.1 with the health token, and the migrate task definition.
- **The health token** in a Secrets Manager secret the module generates, which neither the plan nor
  the state holds.
- **Four CloudWatch alarms** (store down, oldest pending age, refused messages, settled destinations
  failing) on four metrics in the `Pathways` namespace, publishing to an SNS topic you already have,
  and the log group the collector writes those metrics to.
- **PostgreSQL on RDS**, `db.t4g.micro`, in one availability zone, with deletion protection off so a
  destroy goes through.
- **A network load balancer**, internal, with one TCP listener on port 2575 for the channel's MLLP
  source, open to `allowed_cidr_blocks`.
- **A KMS key**, the database's secret, the log groups, the security groups and the two roles.
- **The channel** in `project/`: ADT over MLLP in, each admission out over MLLP to the lab. Its
  `pathways.yaml` turns on the health endpoint on port 9090.

Before it carries real traffic, put `database_multi_az` and `deletion_protection` back to their
defaults.

## What it costs to leave running

We give what bills, not prices: AWS sets those per region and changes them. Price each line in the
[AWS Pricing Calculator](https://calculator.aws/) for your region.

| What | How it bills while it runs |
| --- | --- |
| The engine and the collector, Fargate, 1 vCPU and 2 GiB | per second the task runs, all month |
| The database, `db.t4g.micro`, single-AZ | per hour of the instance, all month |
| Database storage, 50 GiB to start | per GB-month allocated, and backups beyond the database's size |
| The network load balancer | per hour it exists, and per capacity unit used |
| The KMS key, the database's secret and the health token's secret | per month each, and per request or call |
| Four custom metrics and four alarms | per metric per month, and per alarm metric per month |
| CloudWatch Logs | per GB ingested, and per GB-month kept for `log_retention_days` (365) |
| Your SNS topic | per notification delivered |
| Your NAT gateway, already there | per GB the tasks send through it |

The instance, the load balancer and the engine bill by the hour whether or not a message arrives.
The metrics and the alarms bill per month whether or not an alarm fires.

### README.md

```md title="examples/alarms/README.md"
# alarms

The [minimal](../minimal) deployment with the module's alarms on, in an existing VPC:

- one engine on ECS Fargate, one vCPU and 2 GiB, and beside it in the same task a metrics
  collector (AWS Distro for OpenTelemetry) that reads the engine's `/metrics`;
- its PostgreSQL database on RDS, in one availability zone, with deletion protection off;
- a network load balancer with one MLLP listener;
- four CloudWatch alarms (store down, oldest pending age, refused messages, settled destinations
  failing) that publish to an SNS topic you already have;
- the one channel in [`project/`](project), whose `pathways.yaml` turns on the health endpoint on
  port 9090, at 127.0.0.1 inside the task.

The collector authenticates to the health endpoint with a token the module generates and keeps in
Secrets Manager; neither the plan nor the state holds it. It sends CloudWatch only the four metrics
the alarms read, with no channel or destination name.

Every value in [`variables.tf`](variables.tf) is a placeholder. To use it:

1. Copy `project/` into a project `pathways init` made, add the RDS global bundle, the MLLP source's
   certificate and key and the lab's CA under `certs/`, build the project's image and push it.
2. Create the SNS topic the alarms publish to, and subscribe to it.
3. Pick the collector's version on
   [public.ecr.aws/aws-observability/aws-otel-collector](https://gallery.ecr.aws/aws-observability/aws-otel-collector)
   and pin it by the digest the registry gives for it.
4. Set the variables: your VPC and subnets, both images by digest, the master key's secret, the
   topic, the networks your MLLP sender connects from and the lab's network.
5. Plan and apply from your own pipeline, with your own credentials. CI here only runs
   `terraform validate` and a mocked `terraform test` on this directory; nothing in this repository
   applies it.

The docs site's page for this example lists what each part bills for each month.
```

### main.tf

```hcl title="examples/alarms/main.tf"
# The minimal deployment with the module's alarms on: one engine on ECS Fargate, its PostgreSQL
# database and one MLLP channel, plus a metrics collector beside the engine in its task and four
# CloudWatch alarms on the metrics the engine serves, each publishing to an SNS topic you already
# have.
#
# The collector reads /metrics on the engine's health endpoint, at 127.0.0.1 inside the task, with a
# token the module generates in Secrets Manager and gives to both containers. project/pathways.yaml
# turns the health endpoint on at the port alarms_health_port names.
#
# Every value here is a placeholder: the VPC and subnet ids, the account id 123456789012, the image
# digests, the secret ARN and the topic ARN. Put your own in before you plan.

provider "aws" {
  region = var.region

  default_tags {
    tags = {
      Project = "pathways-alarms"
    }
  }
}

module "pathways" {
  source = "../.."

  name   = "alarms"
  vpc_id = var.vpc_id

  private_subnet_ids  = var.private_subnet_ids
  allowed_cidr_blocks = var.allowed_cidr_blocks

  # Your project's own image, by digest: project/ copied onto the Pathways image.
  image = var.image

  # One vCPU and 2 GiB, the module's default size: the collector shares the task with the engine.
  cpu    = 1024
  memory = 2048

  # The channel's MLLP source, in project/channels/adt-to-lab/channel.yaml.
  mllp_sources = {
    adt = { port = 2575 }
  }
  probe_port = 9091

  # HTTPS anywhere is the default rule (the image registry, Secrets Manager and CloudWatch, which
  # the collector writes the metrics to); the lab rule lets the channel's MLLP destination reach
  # the lab, and nowhere else on that port.
  egress_rules = {
    https = {
      port        = 443
      cidr_blocks = ["0.0.0.0/0"]
    }
    lab = {
      port        = 2576
      cidr_blocks = var.lab_cidr_blocks
    }
  }

  environment = {
    PATHWAYS_STORAGE = "postgres"
  }
  secrets = {
    PATHWAYS_KEY_2026_11 = var.master_key_secret_arn
  }

  # The alarms: the health endpoint on 9090 (project/pathways.yaml), the collector's image by
  # digest, and the topic they publish to. The thresholds are the module's defaults, written out.
  alarms_enabled                    = true
  alarms_sns_topic_arn              = var.alarms_sns_topic_arn
  alarms_collector_image            = var.collector_image
  alarms_health_port                = 9090
  alarms_store_down_minutes         = 2
  alarms_oldest_pending_age_seconds = 600
  alarms_refused_messages_threshold = 0
  alarms_settled_failed_threshold   = 0

  # One availability zone and no deletion protection, so that trying it out costs less and a
  # destroy succeeds. The module's defaults are Multi-AZ and protected.
  database_multi_az       = false
  database_instance_class = "db.t4g.micro"
  deletion_protection     = false
}
```

### project/channels/adt-to-lab/channel.yaml

```yaml title="examples/alarms/project/channels/adt-to-lab/channel.yaml"
# One channel: take ADT over MLLP from the hospital system and send each admission on to the lab's
# MLLP receiver. The lab's address is a placeholder.
name: adt-to-lab
format: hl7v2

source:
  mllp:
    # mllp_sources.adt in the example's main.tf: the network load balancer passes this port through.
    port: 2575
    host: 0.0.0.0
    # The engine terminates TLS itself. Add the certificate and key to the image.
    tls:
      cert: ../../certs/server.pem
      key: ../../certs/server.key

transform: ./transform.ts

destinations:
  - mllp:
      # egress_rules.lab in the example's main.tf lets the engine reach this port.
      host: lab.example.com
      port: 2576
      tls:
        ca: ../../certs/lab-ca.pem
```

### project/channels/adt-to-lab/transform.ts

```ts title="examples/alarms/project/channels/adt-to-lab/transform.ts"
// Only admissions go to the lab, addressed to it in MSH-5. Every other message is filtered out.
import type { Transform } from "@cosyte/pathways";

export default ((msg) => {
  if (!msg.is("ADT^A01")) return null;
  msg.setField("MSH.5", "LAB");
  return msg;
}) satisfies Transform;
```

### project/pathways.yaml

```yaml title="examples/alarms/project/pathways.yaml"
# The Pathways project this example deploys: copy it into a project `pathways init` made, build the
# project's image (its Dockerfile names the Pathways image by digest) and pass that image's digest as
# the example's image variable. Every value the module sets reaches the engine as an environment
# variable this file reads with { env: NAME }.

storage:
  kind: { env: PATHWAYS_STORAGE, default: sqlite }
  postgres:
    # The module writes the database's URL to a secret ECS injects as PATHWAYS_DATABASE_URL.
    url: { env: PATHWAYS_DATABASE_URL }
    # The RDS global bundle, https://truststore.pki.rds.amazonaws.com/global/global-bundle.pem, added
    # to the image: the database refuses connections without TLS.
    tls: { ca: certs/rds-global-bundle.pem }

encryption:
  # 32 random bytes in base64, in a Secrets Manager secret the example passes as secrets.
  keys: [{ id: "2026-11", env: PATHWAYS_KEY_2026_11 }]
  current: "2026-11"

# The load balancer checks /readyz here, and ECS runs `pathways probe` against /livez. host:
# 0.0.0.0 lets them reach it; it carries no message.
probes:
  port: 9091
  host: 0.0.0.0
  plaintext: true

# The health endpoint, which serves /metrics to the collector beside the engine. It keeps its
# default host, 127.0.0.1, so only the task itself reaches it, and plain HTTP over that loopback. It
# asks for the bearer token in PATHWAYS_HEALTH_TOKEN, which the module generates and gives to the
# engine and the collector alike. The port is the module's alarms_health_port.
health:
  port: 9090
  plaintext: true
```
