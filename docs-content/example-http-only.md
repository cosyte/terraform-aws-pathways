# The http-only example

`examples/http-only` takes every source over HTTPS, behind one application load balancer.

## What it deploys

In an existing VPC, with a NAT gateway you already have:

- **One engine** on ECS Fargate, 1 vCPU and 2 GiB, and the migrate task definition.
- **PostgreSQL on RDS**, `db.t4g.medium`, Multi-AZ, deletion protection on.
- **An application load balancer**, internal, with an HTTPS listener on 8443, presenting your ACM
  certificate under the `ELBSecurityPolicy-TLS13-1-2-2021-06` policy and forwarding to the engine
  over HTTPS again (`http_target_protocol`).
- **No network load balancer.**
- **The KMS key**, the database's secret, the log groups, the security groups and the roles.
- **The channel** in `project/`: JSON orders over HTTPS in, checked against a bearer token from
  Secrets Manager (`ORDERS_TOKEN`), and posted on to the lab's API over HTTPS.

## When to choose it

When your senders speak HTTP: FHIR, JSON or XML APIs, webhooks, or HL7 v2 over HTTP.

## What it does not cover

- MLLP sources: see [mllp-only](./example-mllp-only.md).
- The DNS name on your certificate: create an alias record pointing at `alb_dns_name`.
- An internet-facing listener, a web application firewall, mutual TLS at the load balancer, and the
  load balancer's access logs.

## What it costs to leave running

We give what bills, not prices: AWS sets those per region and changes them. Price each line in the
[AWS Pricing Calculator](https://calculator.aws/) for your region.

| What | How it bills while it runs |
| --- | --- |
| The engine, Fargate, 1 vCPU and 2 GiB | per second the task runs, all month |
| The database, `db.t4g.medium`, Multi-AZ | per hour of the instance, twice over for the standby, all month |
| Database storage, 50 GiB to start | per GB-month allocated, twice over with Multi-AZ, and backups beyond the database's size |
| The application load balancer | per hour it exists, and per capacity unit used |
| The KMS key and two secrets | per month each, and per request or call |
| CloudWatch Logs | per GB ingested, and per GB-month kept for `log_retention_days` (365) |
| Your NAT gateway, already there | per GB the tasks send through it, the lab's API calls included |

```md title="examples/http-only/README.md"
# http-only

Every source is HTTPS, behind one internal application load balancer.

## What it builds

In an existing VPC, with a NAT gateway you already have:

- one engine on ECS Fargate, 1 vCPU and 2 GiB, and the migrate task definition;
- PostgreSQL on RDS, Multi-AZ, `db.t4g.medium`, with deletion protection on (the module's defaults);
- one internal application load balancer with an HTTPS listener on 8443, presenting your ACM
  certificate under the `ELBSecurityPolicy-TLS13-1-2-2021-06` policy, dropping invalid headers, and
  forwarding to the engine over HTTPS. No network load balancer;
- the KMS key, the secret, the log groups, the security groups and the roles;
- the one channel in [`project/`](project): JSON orders over HTTPS in, checked against a bearer token
  from Secrets Manager, and posted on to the lab's API over HTTPS.

## When to choose it

When your senders speak HTTP: FHIR, JSON or XML APIs, webhooks, or HL7 v2 over HTTP. The load
balancer gives you an ACM certificate that renews on its own and a TLS policy AWS maintains, in front
of an engine that also serves TLS, so nothing is in the clear on either hop.

## What it costs

We give what bills, not prices: AWS sets those per region and changes them.

- Fargate, per second, for 1 vCPU and 2 GiB, all month.
- The database instance per hour, twice over for Multi-AZ; storage per GB-month, twice over.
- One application load balancer per hour and per load balancer capacity unit, which grows with new
  connections, active connections, bytes and rule evaluations.
- The KMS key, the two secrets, and CloudWatch Logs per GB ingested and stored.
- Your NAT gateway, per GB the tasks send through it, the lab's API calls included.

## What it does not cover

- MLLP sources: see [`mllp-only`](../mllp-only), or add `mllp_sources`.
- The DNS name: create an alias record for the name on your certificate, pointing at
  `alb_dns_name`.
- An internet-facing listener. `load_balancer_internal = false` with public subnets makes one, and
  then `allowed_cidr_blocks` is all that stands between the internet and your listener: keep it to
  your senders' addresses. This example keeps it internal.
- A web application firewall, mutual TLS at the load balancer, and the load balancer's access logs.

## Use it

Every value in [`variables.tf`](variables.tf) is a placeholder. Request or import the certificate in
ACM, store the bearer token in a secret, copy `project/` into a project `pathways init` made, add the
RDS global bundle and the source's certificate and key under `certs/`, build the image and push it,
set the variables, then plan and apply from your own pipeline with your own credentials. CI here
validates this directory and tests it against mocked providers (`tests/example-http-only`); nothing in
this repository applies it.
```

### main.tf

```hcl title="examples/http-only/main.tf"
# HTTP only: every source is HTTPS, behind one internal application load balancer, and no network
# load balancer exists. One channel takes orders as JSON over HTTPS from an ordering system and
# sends each on over HTTPS to the lab's API. The load balancer terminates TLS with your ACM
# certificate under a TLS 1.3 policy, and connects to the engine over HTTPS again, so the message is
# encrypted on both hops.
#
# Every value here is a placeholder: the VPC and subnet ids, the account id 123456789012, the image
# digest, the certificate and the secret ARNs. Put your own in before you plan.

provider "aws" {
  region = var.region

  default_tags {
    tags = {
      Project = "pathways-http-only"
    }
  }
}

module "pathways" {
  source = "../.."

  name   = "http-only"
  vpc_id = var.vpc_id

  private_subnet_ids  = var.private_subnet_ids
  allowed_cidr_blocks = var.allowed_cidr_blocks

  image = var.image

  # One HTTPS listener on the application load balancer, on the source's own port. No mllp_sources,
  # so no network load balancer.
  http_sources = {
    orders = { port = 8443 }
  }
  alb_certificate_arn = var.alb_certificate_arn

  # The engine's HTTP source has its own tls block, so the load balancer reaches it over HTTPS (the
  # module's default), written out here.
  http_target_protocol = "HTTPS"
  probe_port           = 9091

  # HTTPS anywhere is the default rule, and the lab's API is HTTPS too: one rule covers the AWS APIs
  # and the destination. Narrow it to the lab's network and VPC endpoints when you have them.
  egress_rules = {
    https = {
      port        = 443
      cidr_blocks = ["0.0.0.0/0"]
    }
  }

  environment = {
    PATHWAYS_STORAGE = "postgres"
  }
  secrets = {
    PATHWAYS_KEY_2026_11 = var.master_key_secret_arn
    # The bearer token the ordering system sends, which the channel's source checks.
    ORDERS_TOKEN = var.orders_token_secret_arn
  }
}
```

### project/channels/orders-in/channel.yaml

```yaml title="examples/http-only/project/channels/orders-in/channel.yaml"
# One channel: take orders as JSON over HTTPS from the ordering system and post each on to the lab's
# API over HTTPS. The lab's URL is a placeholder.
name: orders-in
format: json

source:
  http:
    # http_sources.orders in the example's main.tf: the application load balancer listens on this
    # port and forwards to it over HTTPS.
    port: 8443
    host: 0.0.0.0
    path: /orders
    # The engine serves TLS itself as well, so the load balancer's hop to it is encrypted. Add the
    # certificate and key to the image.
    tls:
      cert: ../../certs/server.pem
      key: ../../certs/server.key
    # The module injects the secret as ORDERS_TOKEN.
    auth:
      bearer: { env: ORDERS_TOKEN }
    maxBytes: 5MB

destinations:
  - http:
      url: https://lab.example.com/orders
```

### project/pathways.yaml

```yaml title="examples/http-only/project/pathways.yaml"
# The Pathways project this example deploys: copy it into a project `pathways init` made, build the
# project's image (its Dockerfile names the Pathways image by digest) and pass that image's digest as
# the example's image variable. Every value the module sets reaches the engine as an environment
# variable this file reads with { env: NAME }.

storage:
  kind: { env: PATHWAYS_STORAGE, default: sqlite }
  postgres:
    # The module writes the database's URL to a secret ECS injects as PATHWAYS_DATABASE_URL.
    url: { env: PATHWAYS_DATABASE_URL }
    # The RDS global bundle, https://truststore.pki.rds.amazonaws.com/global/global-bundle.pem, added
    # to the image: the database refuses connections without TLS.
    tls: { ca: certs/rds-global-bundle.pem }

encryption:
  # 32 random bytes in base64, in a Secrets Manager secret the example passes as secrets.
  keys: [{ id: "2026-11", env: PATHWAYS_KEY_2026_11 }]
  current: "2026-11"

# The load balancer checks /readyz here, and ECS runs `pathways probe` against /livez. host:
# 0.0.0.0 lets them reach it; it carries no message.
probes:
  port: 9091
  host: 0.0.0.0
  plaintext: true
```
