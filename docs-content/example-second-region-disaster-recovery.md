# A second region with promotion (not yet supported)

`examples/second-region-disaster-recovery` holds a README and no Terraform, on purpose: the shape cannot run safely yet,
and we will not ship an example that deploys it.

## What it deploys

Nothing yet. Once it is supported: a second deployment in another region, with a replica of the
database kept current, promoted and started when the first region fails.

## What it waits on

**Promotion to a second region in Pathways.** The engine lease keeps two engines from delivering
the same message on one database, but a promoted replica is a second database: the first
region's engine, still running behind a network split, would keep delivering too. Safe promotion
needs the engine to fence the old region off, which is not in a released Pathways yet.

Once that is in, the folder gets its example, written to the engine's design and tested like the
others.

## What to use today

[cross-region-backup](./example-cross-region-backup.md): the database's backups replicated to a
second region, and a restore there by hand.

## What it costs to leave running

Nothing: there is nothing here to deploy.

## Files

Every file of `examples/second-region-disaster-recovery`, as this release holds it. This section is generated by `scripts/docs.sh`, and CI fails when it no longer matches the folder.

### README.md

```md title="examples/second-region-disaster-recovery/README.md"
# second-region-disaster-recovery

**Not yet supported.** This folder holds no Terraform on purpose: the shape it names cannot run
safely yet, and we will not ship an example that deploys it.

## What it would build

A second deployment in another region, ready to run: a replica of the database kept current, the
image and the master key there already, and a way to promote the replica and start the engine on it
when the first region fails, in minutes rather than the hour or more a restore takes.

## What it waits on

**Promotion to a second region in Pathways.** The engine lease keeps two engines from delivering the
same message, but only on one database. A promoted replica is a second database: the engine in the
first region, if it is still running behind a network split, would keep delivering from its copy
while the second region delivers from the other, and a destination would get messages twice. Safe
promotion needs the engine to fence the old region off once the new one takes over, and that is not
in a released Pathways yet.

Once it is, this folder gets the example, written to the engine's design and tested here like the
others.

## What to use today

[`cross-region-backup`](../cross-region-backup): the database's automated backups replicated to a
second region, and a restore there by hand, step by step, once you have stopped the first region's
engine.

## What it costs

Nothing: there is nothing here to deploy.

## What it does not cover

Everything, until the engine supports it.
```
