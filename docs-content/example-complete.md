# The complete example

`examples/complete` is a whole root module that stands up Pathways end to end: a hospital system
sends ADT over MLLP, the channel writes each admission to the bucket, and the lab picks the files up
over SFTP.

## What it deploys

In an existing VPC, with a NAT gateway you already have:

- **One engine** on ECS Fargate, 1 vCPU and 2 GiB, as a service of one task, and the migrate task
  definition beside it.
- **PostgreSQL on RDS**, `db.t4g.medium`, Multi-AZ, with 50 GiB of storage that may grow to 200, 14
  days of backups, and deletion protection on.
- **A network load balancer**, internal, with one TCP listener on port 2575 for the channel's MLLP
  source, open to `allowed_cidr_blocks`.
- **An S3 bucket**, encrypted under the module's key and versioned, with its access log bucket. Its
  lifecycle rules remove noncurrent versions after 30 days, unfinished uploads after 7, and what the
  lab has not picked up from `partners/lab/outbox/` after 90.
- **An SFTP server**, internal, open on port 22 to `sftp_allowed_cidr_blocks`, with one user, `lab`,
  whose home is `partners/lab`.
- **A KMS key**, the database's secret, the log groups, the security groups and the roles.
- **The channel** in `project/`: ADT over MLLP in, each admission (ADT A01) written to
  `partners/lab/outbox` in the bucket, which the lab sees as `/outbox`.

## What it costs to leave running

We give what bills, not prices: AWS sets those per region and changes them. Price each line in the
[AWS Pricing Calculator](https://calculator.aws/) for your region.

| What | How it bills while it runs |
| --- | --- |
| The engine, Fargate, 1 vCPU and 2 GiB | per second the task runs, all month |
| The database, `db.t4g.medium`, Multi-AZ | per hour of the instance, twice over for the standby, all month |
| Database storage, 50 GiB to start | per GB-month allocated, twice over with Multi-AZ, and backups beyond the database's size |
| The network load balancer | per hour it exists, and per capacity unit used |
| The SFTP server | per hour the SFTP protocol is enabled, whether or not anyone connects, and per GB transferred |
| The bucket and its log bucket | per GB-month stored, noncurrent versions included, and per request; the channel's source does not poll it here |
| The KMS key and the database's secret | per month each, and per request or call |
| CloudWatch Logs | per GB ingested, and per GB-month kept for `log_retention_days` (365) |
| Your NAT gateway, already there | per GB the tasks send through it |

The SFTP server's hourly charge is often the largest line of a small deployment like this one. The
instance, the load balancer, the SFTP server and the engine bill by the hour whether or not a message
arrives.

### README.md

```md title="examples/complete/README.md"
# complete

Pathways on ECS Fargate end to end, in an existing VPC:

- the engine and its PostgreSQL database;
- an S3 bucket the engine reaches through its task role, named to it as `PATHWAYS_BUCKET`;
- an SFTP server in front of the bucket, for one partner, the lab, whose home is `partners/lab`;
- the one channel in [`project/`](project) that joins them: ADT over MLLP in, admissions out to
  `partners/lab/outbox` in the bucket, which the lab sees as `/outbox` over SFTP.

Every value in [`variables.tf`](variables.tf) is a placeholder. To use it:

1. Copy `project/` into a project `pathways init` made, add the RDS global bundle and the MLLP
   source's certificate and key under `certs/`, build the project's image and push it.
2. Set the variables: your VPC and subnets, the image by digest, the master key's secret, the
   networks your MLLP senders and the lab connect from, and the lab's SSH public key.
3. Plan and apply from your own pipeline, with your own credentials. CI here only runs
   `terraform validate` on this directory; nothing in this repository applies it.

The README at the repository root lists what each part costs each month.
```

### main.tf

```hcl title="examples/complete/main.tf"
# Pathways on ECS Fargate end to end, in an existing VPC: the engine and its PostgreSQL database,
# an S3 bucket the engine reaches through its task role, an SFTP server in front of that bucket for
# one partner, and the one channel in project/ that joins them. A hospital system sends ADT over
# MLLP; the channel writes each admission to the bucket under partners/lab/outbox, and the lab
# picks the files up over SFTP from its home, partners/lab.
#
# Every value here is a placeholder: the VPC and subnet ids, the account id 123456789012, the image
# digest, the secret ARN and the SSH key. Put your own in before you plan.

provider "aws" {
  region = var.region

  default_tags {
    tags = {
      Project = "integration"
    }
  }
}

module "pathways" {
  source = "../.."

  name   = "integration"
  vpc_id = var.vpc_id

  private_subnet_ids  = var.private_subnet_ids
  allowed_cidr_blocks = var.allowed_cidr_blocks

  # Your project's own image, by digest: project/ copied onto the Pathways image.
  image = var.image

  cpu    = 1024
  memory = 2048

  # The channel's MLLP source, in project/channels/adt-to-lab/channel.yaml.
  mllp_sources = {
    adt = { port = 2575 }
  }
  probe_port = 9091

  environment = {
    PATHWAYS_STORAGE = "postgres"
  }
  secrets = {
    PATHWAYS_KEY_2026_11 = var.master_key_secret_arn
  }

  # The database: PostgreSQL on RDS, Multi-AZ. The defaults are kept; see variables.tf.
  database_instance_class = "db.t4g.medium"

  # The bucket. The engine gets its name as PATHWAYS_BUCKET, and its task role may use it.
  bucket_enabled = true
  bucket_lifecycle_rules = {
    default = {
      noncurrent_version_expiration_days     = 30
      abort_incomplete_multipart_upload_days = 7
    }
    # What the lab has not picked up in 90 days goes.
    outbox = {
      prefix          = "partners/lab/outbox/"
      expiration_days = 90
    }
  }

  # SFTP for the lab, from its network only.
  sftp_enabled             = true
  sftp_allowed_cidr_blocks = var.sftp_allowed_cidr_blocks
  sftp_users = {
    lab = {
      public_keys = [var.lab_public_key]
      home_prefix = "partners/lab"
    }
  }
}
```

### project/channels/adt-to-lab/channel.yaml

```yaml title="examples/complete/project/channels/adt-to-lab/channel.yaml"
# One channel: take ADT over MLLP from the hospital system, keep the admissions, and write each to the
# module's bucket under partners/lab/outbox, where the lab picks it up over SFTP. The lab's SFTP home
# is partners/lab, so it sees the files under /outbox.
name: adt-to-lab
format: hl7v2

source:
  mllp:
    # mllp_sources.adt in the example's main.tf: the network load balancer passes this port through.
    port: 2575
    host: 0.0.0.0
    # The engine terminates TLS itself. Add the certificate and key to the image.
    tls:
      cert: ../../certs/server.pem
      key: ../../certs/server.key

transform: ./transform.ts

destinations:
  - file:
      dir: partners/lab/outbox
      s3:
        # The module sets PATHWAYS_BUCKET to its bucket's name. The engine's task role may use the
        # bucket, and the AWS SDK finds that role and the region on its own: no credential here.
        bucket: { env: PATHWAYS_BUCKET }
```

### project/channels/adt-to-lab/transform.ts

```ts title="examples/complete/project/channels/adt-to-lab/transform.ts"
// Only admissions go to the lab, addressed to it in MSH-5. Every other message is filtered out.
import type { Transform } from "@cosyte/pathways";

export default ((msg) => {
  if (!msg.is("ADT^A01")) return null;
  msg.setField("MSH.5", "LAB");
  return msg;
}) satisfies Transform;
```

### project/pathways.yaml

```yaml title="examples/complete/project/pathways.yaml"
# The Pathways project this example deploys: copy it into a project `pathways init` made, build the
# project's image (its Dockerfile names the Pathways image by digest) and pass that image's digest as
# the example's image variable. Every value the module sets reaches the engine as an environment
# variable this file reads with { env: NAME }.

storage:
  kind: { env: PATHWAYS_STORAGE, default: sqlite }
  postgres:
    # The module writes the database's URL to a secret ECS injects as PATHWAYS_DATABASE_URL.
    url: { env: PATHWAYS_DATABASE_URL }
    # The RDS global bundle, https://truststore.pki.rds.amazonaws.com/global/global-bundle.pem, added
    # to the image: the database refuses connections without TLS.
    tls: { ca: certs/rds-global-bundle.pem }

encryption:
  # 32 random bytes in base64, in a Secrets Manager secret the example passes as secrets.
  keys: [{ id: "2026-11", env: PATHWAYS_KEY_2026_11 }]
  current: "2026-11"

# The load balancers check /readyz here, and ECS runs `pathways probe` against /livez. host:
# 0.0.0.0 lets them reach it; it carries no message.
probes:
  port: 9091
  host: 0.0.0.0
  plaintext: true
```
