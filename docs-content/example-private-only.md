# The private-only example

`examples/private-only` has no path to or from the internet: the engine reaches the AWS APIs it
needs through VPC endpoints the example creates.

## What it deploys

In an existing VPC whose engine subnets route to no internet gateway and no NAT gateway:

- **One engine** on ECS Fargate, 1 vCPU and 2 GiB, with no public address, and the migrate task
  definition.
- **PostgreSQL on RDS**, `db.t4g.medium`, Multi-AZ, not publicly accessible, deletion protection on.
- **A network load balancer**, internal, with one MLLP listener.
- **VPC interface endpoints** for `ecr.api`, `ecr.dkr`, `secretsmanager` and `logs`, with private
  DNS, behind a security group that admits the engine alone on 443, and **an S3 gateway endpoint**
  for the image's layers.
- **The engine's egress** narrowed to the VPC's own network on 443, S3's prefix list on 443, and the
  lab's network on 2576. No rule reaches `0.0.0.0/0`.
- **The KMS key**, the database's secret, the log groups, the security groups and the roles.
- **The channel** in `project/`: ADT over MLLP in, admissions over MLLP out to the lab.

## When to choose it

When your security policy says the integration engine has no path to or from the internet.

## What it does not cover

- A destination on the internet, or an image in another registry: both need a NAT gateway or a
  proxy.
- Secrets in SSM Parameter Store, or a customer managed key the task calls: add the `ssm` or `kms`
  endpoint.
- Your private network's routes, network ACLs and DNS.

## What it costs to leave running

We give what bills, not prices: AWS sets those per region and changes them. Price each line in the
[AWS Pricing Calculator](https://calculator.aws/) for your region.

| What | How it bills while it runs |
| --- | --- |
| Four interface endpoints | per hour each, in each of two availability zones, and per GB processed |
| The S3 gateway endpoint | no hourly or per GB charge |
| The engine, Fargate, 1 vCPU and 2 GiB | per second the task runs, all month |
| The database, `db.t4g.medium`, Multi-AZ | per hour of the instance, twice over for the standby, all month |
| Database storage, 50 GiB to start | per GB-month allocated, twice over with Multi-AZ, and backups beyond the database's size |
| The network load balancer | per hour it exists, and per capacity unit used |
| The KMS key and the database's secret | per month each, and per request or call |
| CloudWatch Logs | per GB ingested, and per GB-month kept for `log_retention_days` (365) |

There is no NAT gateway to pay for. Price the endpoints against the NAT gateway they replace: this
shape is chosen for its isolation, not its price.

### README.md

```md title="examples/private-only/README.md"
# private-only

Nothing reachable from the internet, and nothing reaching out to it: no public ingress, and no NAT
gateway.

## What it builds

In an existing VPC whose engine subnets route to no internet gateway and no NAT gateway:

- one engine on ECS Fargate, 1 vCPU and 2 GiB, with no public address, and the migrate task
  definition;
- PostgreSQL on RDS, Multi-AZ, `db.t4g.medium`, not publicly accessible, with deletion protection on
  (the module's defaults);
- an internal network load balancer with one MLLP listener, which resolves to private addresses
  only;
- VPC interface endpoints for `ecr.api`, `ecr.dkr`, `secretsmanager` and `logs`, with private DNS,
  behind a security group that admits the engine alone on 443, and an S3 gateway endpoint for the
  image's layers;
- the engine's egress narrowed to the VPC's own network on 443 (the endpoints), S3's prefix list on
  443 (the gateway endpoint), and the lab's network on 2576. No rule reaches `0.0.0.0/0`;
- the KMS key, the secret, the log groups, the security groups and the roles;
- the one channel in [`project/`](project): ADT over MLLP in, admissions over MLLP out to the lab.

## When to choose it

When your security policy says the integration engine has no path to or from the internet. Senders
and destinations reach it over your private network: a VPN, Direct Connect, a transit gateway or
peering.

## What it costs

We give what bills, not prices: AWS sets those per region and changes them.

- Four interface endpoints, each per hour in each availability zone it is in (two here), and per GB
  processed. Price them against the NAT gateway they replace, which bills per hour and per GB too;
  you choose this shape for its isolation, not its price.
- The S3 gateway endpoint: no hourly or per GB charge.
- Fargate, per second, for 1 vCPU and 2 GiB, all month.
- The database instance per hour, twice over for Multi-AZ; storage per GB-month, twice over.
- The network load balancer per hour and per capacity unit.
- The KMS key, the secret, and CloudWatch Logs per GB ingested and stored.

## What it does not cover

- A destination on the internet: an HTTPS API outside your network needs a NAT gateway or a proxy,
  and an `egress_rules` entry for it. That is no longer this shape.
- An image in another registry: with no NAT gateway the task reaches ECR in its own region alone.
  Copy the image there first.
- The bucket or SFTP: with `bucket_enabled` the engine reaches the bucket through the same S3 gateway
  endpoint; SFTP's endpoint is internal already. Neither is in this example.
- Secrets in SSM Parameter Store, or a customer managed key the task must call: add the `ssm` or
  `kms` interface endpoint.
- Route tables, network ACLs and DNS resolution for your private network: those are your network's.

## Use it

Every value in [`variables.tf`](variables.tf) is a placeholder. Copy `project/` into a project
`pathways init` made, add the RDS global bundle, the MLLP source's certificate and key and the lab's
CA under `certs/`, build the image and push it to ECR in the same region, set the variables, then plan
and apply from your own pipeline with your own credentials. CI here validates this directory and
tests it against mocked providers (`tests/example-private-only`); nothing in this repository applies
it.
```

### main.tf

```hcl title="examples/private-only/main.tf"
# Private only: nothing is reachable from the internet, and nothing reaches out to it. The VPC has no
# internet gateway route and no NAT gateway in the engine's subnets; the engine reaches the AWS APIs
# it needs through VPC endpoints this example creates, and its HTTPS egress goes to the VPC's own
# network and to S3's gateway endpoint alone, not to 0.0.0.0/0. The network load balancer is
# internal, the tasks get no public address, and the database is not publicly accessible: the
# module's defaults, written out here.
#
# Every value here is a placeholder: the VPC, subnet and route table ids, the account id
# 123456789012, the image digest and the secret ARN. Put your own in before you plan.

provider "aws" {
  region = var.region

  default_tags {
    tags = {
      Project = "pathways-private"
    }
  }
}

data "aws_vpc" "this" {
  id = var.vpc_id
}

module "pathways" {
  source = "../.."

  name   = "private"
  vpc_id = var.vpc_id

  private_subnet_ids  = var.private_subnet_ids
  allowed_cidr_blocks = var.allowed_cidr_blocks

  # Internal: the load balancer gets private addresses only (the module's default).
  load_balancer_internal = true

  image = var.image

  mllp_sources = {
    adt = { port = 2575 }
  }
  probe_port = 9091

  # HTTPS to the VPC's own network only, where the interface endpoints below listen, and the lab's
  # MLLP port. S3, for the image's layers, is the rule beside the module call. No rule reaches the
  # internet.
  egress_rules = {
    endpoints = {
      port        = 443
      cidr_blocks = [data.aws_vpc.this.cidr_block]
    }
    lab = {
      port        = 2576
      cidr_blocks = var.lab_cidr_blocks
    }
  }

  environment = {
    PATHWAYS_STORAGE = "postgres"
  }
  secrets = {
    PATHWAYS_KEY_2026_11 = var.master_key_secret_arn
  }
}

# ---------------------------------------------------------------------------
# VPC endpoints: what a Fargate task needs with no NAT gateway
# ---------------------------------------------------------------------------

locals {
  # Pull the image (ecr.api and ecr.dkr, with its layers from S3), read the secrets
  # (secretsmanager) and write the logs (logs).
  interface_endpoints = toset(["ecr.api", "ecr.dkr", "secretsmanager", "logs"])
}

resource "aws_security_group" "endpoints" {
  name        = "pathways-private-endpoints"
  description = "Pathways private: the VPC interface endpoints, reachable from the engine only"
  vpc_id      = var.vpc_id
}

resource "aws_vpc_security_group_ingress_rule" "endpoints_from_engine" {
  security_group_id            = aws_security_group.endpoints.id
  description                  = "HTTPS from the engine"
  referenced_security_group_id = module.pathways.engine_security_group_id
  ip_protocol                  = "tcp"
  from_port                    = 443
  to_port                      = 443
}

resource "aws_vpc_endpoint" "interface" {
  for_each = local.interface_endpoints

  vpc_id              = var.vpc_id
  service_name        = "com.amazonaws.${var.region}.${each.key}"
  vpc_endpoint_type   = "Interface"
  subnet_ids          = var.private_subnet_ids
  security_group_ids  = [aws_security_group.endpoints.id]
  private_dns_enabled = true

  tags = {
    Name = "pathways-private-${each.key}"
  }
}

# S3 is a gateway endpoint: a route in the subnets' route tables, at no hourly charge. ECR serves
# image layers from S3.
resource "aws_vpc_endpoint" "s3" {
  vpc_id            = var.vpc_id
  service_name      = "com.amazonaws.${var.region}.s3"
  vpc_endpoint_type = "Gateway"
  route_table_ids   = var.private_route_table_ids

  tags = {
    Name = "pathways-private-s3"
  }
}

resource "aws_vpc_security_group_egress_rule" "engine_to_s3" {
  security_group_id = module.pathways.engine_security_group_id
  description       = "HTTPS to S3, through the gateway endpoint"
  prefix_list_id    = aws_vpc_endpoint.s3.prefix_list_id
  ip_protocol       = "tcp"
  from_port         = 443
  to_port           = 443
}
```

### project/channels/adt-to-lab/channel.yaml

```yaml title="examples/private-only/project/channels/adt-to-lab/channel.yaml"
# One channel: take ADT over MLLP from the hospital system and send each admission on to the lab's
# MLLP receiver. The lab's address is a placeholder.
name: adt-to-lab
format: hl7v2

source:
  mllp:
    # mllp_sources.adt in the example's main.tf: the network load balancer passes this port through.
    port: 2575
    host: 0.0.0.0
    # The engine terminates TLS itself. Add the certificate and key to the image.
    tls:
      cert: ../../certs/server.pem
      key: ../../certs/server.key

transform: ./transform.ts

destinations:
  - mllp:
      # egress_rules.lab in the example's main.tf lets the engine reach this port.
      host: lab.example.com
      port: 2576
      tls:
        ca: ../../certs/lab-ca.pem
```

### project/channels/adt-to-lab/transform.ts

```ts title="examples/private-only/project/channels/adt-to-lab/transform.ts"
// Only admissions go to the lab, addressed to it in MSH-5. Every other message is filtered out.
import type { Transform } from "@cosyte/pathways";

export default ((msg) => {
  if (!msg.is("ADT^A01")) return null;
  msg.setField("MSH.5", "LAB");
  return msg;
}) satisfies Transform;
```

### project/pathways.yaml

```yaml title="examples/private-only/project/pathways.yaml"
# The Pathways project this example deploys: copy it into a project `pathways init` made, build the
# project's image (its Dockerfile names the Pathways image by digest) and pass that image's digest as
# the example's image variable. Every value the module sets reaches the engine as an environment
# variable this file reads with { env: NAME }.

storage:
  kind: { env: PATHWAYS_STORAGE, default: sqlite }
  postgres:
    # The module writes the database's URL to a secret ECS injects as PATHWAYS_DATABASE_URL.
    url: { env: PATHWAYS_DATABASE_URL }
    # The RDS global bundle, https://truststore.pki.rds.amazonaws.com/global/global-bundle.pem, added
    # to the image: the database refuses connections without TLS.
    tls: { ca: certs/rds-global-bundle.pem }

encryption:
  # 32 random bytes in base64, in a Secrets Manager secret the example passes as secrets.
  keys: [{ id: "2026-11", env: PATHWAYS_KEY_2026_11 }]
  current: "2026-11"

# The load balancer checks /readyz here, and ECS runs `pathways probe` against /livez. host:
# 0.0.0.0 lets them reach it; it carries no message.
probes:
  port: 9091
  host: 0.0.0.0
  plaintext: true
```
