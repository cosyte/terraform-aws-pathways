# The minimal example

`examples/minimal` is a whole root module that calls this one with the fewest pieces a working
deployment needs. The [Quickstart](./quickstart.md) deploys it step by step.

## What it deploys

In an existing VPC, with a NAT gateway you already have:

- **One engine** on ECS Fargate, half a vCPU and 1 GiB, as a service of one task, and the migrate
  task definition beside it.
- **PostgreSQL on RDS**, `db.t4g.micro`, in one availability zone, with 50 GiB of storage that may
  grow to 200, 14 days of backups, and deletion protection off so a destroy goes through.
- **A network load balancer**, internal, with one TCP listener on port 2575 for the channel's MLLP
  source, open to `allowed_cidr_blocks`.
- **A KMS key**, the database's secret, two log groups, the security groups and the two roles.
- **The channel** in `project/`: ADT over MLLP in, each admission (ADT A01) out over MLLP to the lab
  on port 2576, which `egress_rules` lets the engine reach.

No HTTP source, no bucket and no SFTP. Before it carries real traffic, put `database_multi_az` and
`deletion_protection` back to their defaults.

## What it costs to leave running

We give what bills, not prices: AWS sets those per region and changes them. Price each line in the
[AWS Pricing Calculator](https://calculator.aws/) for your region.

| What | How it bills while it runs |
| --- | --- |
| The engine, Fargate, 0.5 vCPU and 1 GiB | per second the task runs, all month |
| The database, `db.t4g.micro`, single-AZ | per hour of the instance, all month |
| Database storage, 50 GiB to start | per GB-month allocated, and backups beyond the database's size |
| The network load balancer | per hour it exists, and per capacity unit used |
| The KMS key and the database's secret | per month each, and per request or call |
| CloudWatch Logs | per GB ingested, and per GB-month kept for `log_retention_days` (365) |
| Your NAT gateway, already there | per GB the tasks send through it |

The instance, the load balancer and the engine bill by the hour whether or not a message arrives.
After a destroy, the final snapshot bills per GB-month until you delete it.

### README.md

```md title="examples/minimal/README.md"
# minimal

The smallest deployment of the module, in an existing VPC:

- one engine on ECS Fargate, half a vCPU and 1 GiB;
- its PostgreSQL database on RDS, in one availability zone, with deletion protection off;
- a network load balancer with one MLLP listener;
- the one channel in [`project/`](project): ADT over MLLP in, admissions over MLLP out to the lab.

No HTTP source, no bucket and no SFTP. It is sized for trying the module out: before it carries real
traffic, put `database_multi_az` and `deletion_protection` back to their defaults (both `true`).

Every value in [`variables.tf`](variables.tf) is a placeholder. To use it:

1. Copy `project/` into a project `pathways init` made, add the RDS global bundle, the MLLP source's
   certificate and key and the lab's CA under `certs/`, build the project's image and push it.
2. Set the variables: your VPC and subnets, the image by digest, the master key's secret, the
   networks your MLLP sender connects from and the lab's network.
3. Plan and apply from your own pipeline, with your own credentials. CI here only runs
   `terraform validate` on this directory; nothing in this repository applies it.

The docs site's page for this example, and the README at the repository root, list what each part
costs each month.
```

### main.tf

```hcl title="examples/minimal/main.tf"
# The smallest deployment: one engine on ECS Fargate and its PostgreSQL database, in an existing
# VPC, with one channel in project/ that takes ADT over MLLP from a hospital system and sends it on
# over MLLP to a lab. No HTTP source, no bucket and no SFTP.
#
# It is sized to try the module out, not to run in production: the database is in one availability
# zone, and deletion protection is off so that a destroy takes it down. Turn both back on (they are
# the module's defaults) before it carries real traffic.
#
# Every value here is a placeholder: the VPC and subnet ids, the account id 123456789012, the image
# digest and the secret ARN. Put your own in before you plan.

provider "aws" {
  region = var.region

  default_tags {
    tags = {
      Project = "pathways-minimal"
    }
  }
}

module "pathways" {
  source = "../.."

  name   = "minimal"
  vpc_id = var.vpc_id

  private_subnet_ids  = var.private_subnet_ids
  allowed_cidr_blocks = var.allowed_cidr_blocks

  # Your project's own image, by digest: project/ copied onto the Pathways image.
  image = var.image

  # Half a vCPU and 1 GiB, half the module's default size: enough for one channel.
  cpu    = 512
  memory = 1024

  # The channel's MLLP source, in project/channels/adt-to-lab/channel.yaml.
  mllp_sources = {
    adt = { port = 2575 }
  }
  probe_port = 9091

  # HTTPS anywhere is the default rule (the image registry, Secrets Manager and CloudWatch Logs);
  # the lab rule lets the channel's MLLP destination reach the lab, and nowhere else on that port.
  egress_rules = {
    https = {
      port        = 443
      cidr_blocks = ["0.0.0.0/0"]
    }
    lab = {
      port        = 2576
      cidr_blocks = var.lab_cidr_blocks
    }
  }

  environment = {
    PATHWAYS_STORAGE = "postgres"
  }
  secrets = {
    PATHWAYS_KEY_2026_11 = var.master_key_secret_arn
  }

  # One availability zone and no deletion protection, so that trying it out costs less and a
  # destroy succeeds. The module's defaults are Multi-AZ and protected.
  database_multi_az       = false
  database_instance_class = "db.t4g.micro"
  deletion_protection     = false
}
```

### project/channels/adt-to-lab/channel.yaml

```yaml title="examples/minimal/project/channels/adt-to-lab/channel.yaml"
# One channel: take ADT over MLLP from the hospital system and send each admission on to the lab's
# MLLP receiver. The lab's address is a placeholder.
name: adt-to-lab
format: hl7v2

source:
  mllp:
    # mllp_sources.adt in the example's main.tf: the network load balancer passes this port through.
    port: 2575
    host: 0.0.0.0
    # The engine terminates TLS itself. Add the certificate and key to the image.
    tls:
      cert: ../../certs/server.pem
      key: ../../certs/server.key

transform: ./transform.ts

destinations:
  - mllp:
      # egress_rules.lab in the example's main.tf lets the engine reach this port.
      host: lab.example.com
      port: 2576
      tls:
        ca: ../../certs/lab-ca.pem
```

### project/channels/adt-to-lab/transform.ts

```ts title="examples/minimal/project/channels/adt-to-lab/transform.ts"
// Only admissions go to the lab, addressed to it in MSH-5. Every other message is filtered out.
import type { Transform } from "@cosyte/pathways";

export default ((msg) => {
  if (!msg.is("ADT^A01")) return null;
  msg.setField("MSH.5", "LAB");
  return msg;
}) satisfies Transform;
```

### project/pathways.yaml

```yaml title="examples/minimal/project/pathways.yaml"
# The Pathways project this example deploys: copy it into a project `pathways init` made, build the
# project's image (its Dockerfile names the Pathways image by digest) and pass that image's digest as
# the example's image variable. Every value the module sets reaches the engine as an environment
# variable this file reads with { env: NAME }.

storage:
  kind: { env: PATHWAYS_STORAGE, default: sqlite }
  postgres:
    # The module writes the database's URL to a secret ECS injects as PATHWAYS_DATABASE_URL.
    url: { env: PATHWAYS_DATABASE_URL }
    # The RDS global bundle, https://truststore.pki.rds.amazonaws.com/global/global-bundle.pem, added
    # to the image: the database refuses connections without TLS.
    tls: { ca: certs/rds-global-bundle.pem }

encryption:
  # 32 random bytes in base64, in a Secrets Manager secret the example passes as secrets.
  keys: [{ id: "2026-11", env: PATHWAYS_KEY_2026_11 }]
  current: "2026-11"

# The load balancer checks /readyz here, and ECS runs `pathways probe` against /livez. host:
# 0.0.0.0 lets them reach it; it carries no message.
probes:
  port: 9091
  host: 0.0.0.0
  plaintext: true
```
