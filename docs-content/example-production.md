# The production example

`examples/production` is the shape to start production from: one engine, the module's protections
kept on, and the database's warm standby.

## What it deploys

In an existing VPC, with a NAT gateway you already have:

- **One engine** on ECS Fargate, 2 vCPU and 4 GiB, as a service of one task, and the migrate task
  definition. ECS replaces the engine if it stops, or if `pathways probe` reports it stalled.
- **PostgreSQL on RDS**, `db.m7g.large`, Multi-AZ: RDS keeps a synchronous standby in a second
  availability zone and fails over to it on its own, under the same hostname. 100 GiB of storage
  that may grow to 500, 35 days of automated backups, deletion protection on, and its storage,
  backups and final snapshot under a KMS key of your own (`database_kms_key_arn`), so they outlive a
  destroy.
- **A network load balancer**, internal, with one MLLP listener on 2575.
- **The module's KMS key**, the database's secret, two log groups, the security groups and the roles.
- **The channel** in `project/`: ADT over MLLP in, each admission out over MLLP to the lab on 2576.

## When to choose it

When one engine is enough for your traffic and a gap of one engine start, while ECS replaces a
failed task, is one your senders retry across.

## What it does not cover

- **A standby engine.** Pathways can run a second engine with `pathways start --standby`, which takes
  the engine lease when the first stops. The module does not run one yet: ECS replaces a task its
  load balancer reports unhealthy, and a standby is not ready by design, so it needs its own design
  and tests first.
- Several active engines, blue and green deploys and a second region, which wait on the engine:
  see [multiple-active-nodes](./example-multiple-active-nodes.md), [blue-green](./example-blue-green.md)
  and [second-region-disaster-recovery](./example-second-region-disaster-recovery.md).
- Alarms: turn them on with `alarms_enabled`, as the [alarms example](./example-alarms.md) does.
- The database's KMS key, which you create and keep outside this example.

## What it costs to leave running

We give what bills, not prices: AWS sets those per region and changes them. Price each line in the
[AWS Pricing Calculator](https://calculator.aws/) for your region.

| What | How it bills while it runs |
| --- | --- |
| The engine, Fargate, 2 vCPU and 4 GiB | per second the task runs, all month |
| The database, `db.m7g.large`, Multi-AZ | per hour of the instance, twice over for the standby, all month |
| Database storage, 100 GiB to start | per GB-month allocated, twice over with Multi-AZ, and backups beyond the database's size over 35 days |
| The network load balancer | per hour it exists, and per capacity unit used |
| Your KMS key, the module's key and the database's secret | per month each, and per request or call |
| CloudWatch Logs | per GB ingested, and per GB-month kept for `log_retention_days` (365) |
| Your NAT gateway, already there | per GB the tasks send through it |

The instance, its standby, the load balancer and the engine bill by the hour whether or not a
message arrives.

  task its load balancer reports unhealthy, and a standby is not ready by design, so it needs its own

### main.tf

```hcl title="examples/production/main.tf"
# Production with one engine: the module's defaults, kept, with the database's warm standby. The
# engine runs as a service of one task; ECS replaces it if it stops or stalls. The database is
# Multi-AZ: RDS keeps a synchronous standby in a second availability zone and fails over to it on
# its own. Deletion protection is on, backups are kept 35 days, and the database's storage, backups
# and final snapshot are under a key of your own, so a destroy of this module cannot make them
# unreadable.
#
# A standby engine (pathways start --standby) is not here: on ECS it needs support in this module
# that is not written yet. See the README.
#
# Every value here is a placeholder: the VPC and subnet ids, the account id 123456789012, the image
# digest, the secret and key ARNs. Put your own in before you plan.

provider "aws" {
  region = var.region

  default_tags {
    tags = {
      Project = "pathways-production"
    }
  }
}

module "pathways" {
  source = "../.."

  name   = "production"
  vpc_id = var.vpc_id

  private_subnet_ids  = var.private_subnet_ids
  allowed_cidr_blocks = var.allowed_cidr_blocks

  # Your project's own image, by digest: project/ copied onto the Pathways image.
  image = var.image

  # Two vCPU and 4 GiB: room for several busy channels. Measure your own load and size to it.
  cpu    = 2048
  memory = 4096

  # The channel's MLLP source, in project/channels/adt-to-lab/channel.yaml.
  mllp_sources = {
    adt = { port = 2575 }
  }
  probe_port = 9091

  egress_rules = {
    https = {
      port        = 443
      cidr_blocks = ["0.0.0.0/0"]
    }
    lab = {
      port        = 2576
      cidr_blocks = var.lab_cidr_blocks
    }
  }

  environment = {
    PATHWAYS_STORAGE = "postgres"
  }
  secrets = {
    PATHWAYS_KEY_2026_11 = var.master_key_secret_arn
  }

  # The database: Multi-AZ and protected from deletion, which are the module's defaults, written out
  # here so a reader sees them. A general purpose instance, room to grow, and the longest automated
  # backup window RDS allows.
  database_multi_az              = true
  deletion_protection            = true
  database_instance_class        = "db.m7g.large"
  database_allocated_storage     = 100
  database_max_allocated_storage = 500
  database_backup_retention_days = 35

  # A key of your own, which this module does not manage, so the final snapshot outlives a destroy.
  database_kms_key_arn = var.database_kms_key_arn
}
```

### project/channels/adt-to-lab/channel.yaml

```yaml title="examples/production/project/channels/adt-to-lab/channel.yaml"
# One channel: take ADT over MLLP from the hospital system and send each admission on to the lab's
# MLLP receiver. The lab's address is a placeholder.
name: adt-to-lab
format: hl7v2

source:
  mllp:
    # mllp_sources.adt in the example's main.tf: the network load balancer passes this port through.
    port: 2575
    host: 0.0.0.0
    # The engine terminates TLS itself. Add the certificate and key to the image.
    tls:
      cert: ../../certs/server.pem
      key: ../../certs/server.key

transform: ./transform.ts

destinations:
  - mllp:
      # egress_rules.lab in the example's main.tf lets the engine reach this port.
      host: lab.example.com
      port: 2576
      tls:
        ca: ../../certs/lab-ca.pem
```

### project/channels/adt-to-lab/transform.ts

```ts title="examples/production/project/channels/adt-to-lab/transform.ts"
// Only admissions go to the lab, addressed to it in MSH-5. Every other message is filtered out.
import type { Transform } from "@cosyte/pathways";

export default ((msg) => {
  if (!msg.is("ADT^A01")) return null;
  msg.setField("MSH.5", "LAB");
  return msg;
}) satisfies Transform;
```

### project/pathways.yaml

```yaml title="examples/production/project/pathways.yaml"
# The Pathways project this example deploys: copy it into a project `pathways init` made, build the
# project's image (its Dockerfile names the Pathways image by digest) and pass that image's digest as
# the example's image variable. Every value the module sets reaches the engine as an environment
# variable this file reads with { env: NAME }.

storage:
  kind: { env: PATHWAYS_STORAGE, default: sqlite }
  postgres:
    # The module writes the database's URL to a secret ECS injects as PATHWAYS_DATABASE_URL.
    url: { env: PATHWAYS_DATABASE_URL }
    # The RDS global bundle, https://truststore.pki.rds.amazonaws.com/global/global-bundle.pem, added
    # to the image: the database refuses connections without TLS.
    tls: { ca: certs/rds-global-bundle.pem }

encryption:
  # 32 random bytes in base64, in a Secrets Manager secret the example passes as secrets.
  keys: [{ id: "2026-11", env: PATHWAYS_KEY_2026_11 }]
  current: "2026-11"

# The load balancer checks /readyz here, and ECS runs `pathways probe` against /livez. host:
# 0.0.0.0 lets them reach it; it carries no message.
probes:
  port: 9091
  host: 0.0.0.0
  plaintext: true
```
