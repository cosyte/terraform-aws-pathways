# The mllp-only example

`examples/mllp-only` takes every source over MLLP, behind one network load balancer that passes each
connection straight to the engine, which terminates its own TLS.

## What it deploys

In an existing VPC, with a NAT gateway you already have:

- **One engine** on ECS Fargate, 1 vCPU and 2 GiB, and the migrate task definition.
- **PostgreSQL on RDS**, `db.t4g.medium`, Multi-AZ, deletion protection on.
- **A network load balancer**, internal, with two TCP listeners: 2575 for ADT and 2577 for results,
  both open to the hospital's and the lab's networks.
- **No application load balancer**, no ACM certificate, no bucket and no SFTP.
- **The KMS key**, the database's secret, the log groups, the security groups and the roles.
- **Two channels** in `project/`: ADT from the hospital to the lab on 2576, and results from the lab
  to the EHR on 2578, each destination allowed in `egress_rules` and nowhere else.

## When to choose it

When your interfaces are HL7 v2 over MLLP: most hospital ADT, orders and results feeds.

## What it does not cover

- HTTP sources: see [http-only](./example-http-only.md).
- One network per listener: `allowed_cidr_blocks` opens every MLLP listener to every network in it.
- More than five sources: an ECS service attaches to at most five target groups, one per source.
- An internet-facing listener.

## What it costs to leave running

We give what bills, not prices: AWS sets those per region and changes them. Price each line in the
[AWS Pricing Calculator](https://calculator.aws/) for your region.

| What | How it bills while it runs |
| --- | --- |
| The engine, Fargate, 1 vCPU and 2 GiB | per second the task runs, all month |
| The database, `db.t4g.medium`, Multi-AZ | per hour of the instance, twice over for the standby, all month |
| Database storage, 50 GiB to start | per GB-month allocated, twice over with Multi-AZ, and backups beyond the database's size |
| The network load balancer, two listeners | per hour it exists, and per capacity unit used: long-lived MLLP connections count as active all month |
| The KMS key and the database's secret | per month each, and per request or call |
| CloudWatch Logs | per GB ingested, and per GB-month kept for `log_retention_days` (365) |
| Your NAT gateway, already there | per GB the tasks send through it |

```md title="examples/mllp-only/README.md"
# mllp-only

Every source is HL7 v2 over MLLP, behind one internal network load balancer.

## What it builds

In an existing VPC, with a NAT gateway you already have:

- one engine on ECS Fargate, 1 vCPU and 2 GiB, and the migrate task definition;
- PostgreSQL on RDS, Multi-AZ, `db.t4g.medium`, with deletion protection on (the module's defaults);
- one internal network load balancer with two TCP listeners, 2575 for ADT and 2577 for results,
  each passed straight through to the engine, which terminates its own TLS. Both are open to the
  hospital's and the lab's networks;
- no application load balancer, no ACM certificate, no bucket and no SFTP;
- the KMS key, the secret, the log groups, the security groups and the roles;
- the two channels in [`project/`](project): ADT from the hospital to the lab on 2576, and results
  from the lab to the EHR on 2578, each destination allowed in `egress_rules` and nowhere else.

## When to choose it

When your interfaces are HL7 v2 over MLLP, which is most hospital ADT, orders and results feeds.
TLS ends in the engine, so the certificates and keys are in your image and the load balancer never
sees a message in the clear.

## What it costs

We give what bills, not prices: AWS sets those per region and changes them.

- Fargate, per second, for 1 vCPU and 2 GiB, all month.
- The database instance per hour, twice over for Multi-AZ; storage per GB-month, twice over.
- One network load balancer per hour and per capacity unit, which grows with new connections, active
  connections and bytes: long-lived MLLP connections count as active all month. A second listener
  adds no hourly charge.
- The KMS key, the secret, and CloudWatch Logs per GB ingested and stored.
- Your NAT gateway, per GB the tasks send through it.

## What it does not cover

- HTTP sources: see [`http-only`](../http-only), or add `http_sources` and a certificate.
- One network per listener: `allowed_cidr_blocks` opens every MLLP listener to every network in it.
  To keep the lab off the ADT port, narrow each sender with your network's own rules, or run two
  deployments.
- More than five sources: an ECS service attaches to at most five target groups, one per source, so
  the module refuses a sixth.
- An internet-facing listener. Partners reach this one over your VPN or another private link.

## Use it

Every value in [`variables.tf`](variables.tf) is a placeholder. Copy `project/` into a project
`pathways init` made, add the RDS global bundle, the MLLP sources' certificate and key and the lab's
and EHR's CAs under `certs/`, build the image and push it, set the variables, then plan and apply
from your own pipeline with your own credentials. CI here validates this directory and tests it
against mocked providers (`tests/example-mllp-only`); nothing in this repository applies it.
```

### main.tf

```hcl title="examples/mllp-only/main.tf"
# MLLP only: every source is HL7 v2 over MLLP, behind one internal network load balancer, and every
# destination is MLLP too. No application load balancer, no certificate in ACM, no bucket and no
# SFTP. Two channels: ADT from the hospital system to the lab, and results from the lab back to the
# EHR. The network load balancer passes each TCP connection straight through to the engine, which
# terminates its own TLS, so the certificates live in the image, not in AWS.
#
# Every value here is a placeholder: the VPC and subnet ids, the account id 123456789012, the image
# digest and the secret ARN. Put your own in before you plan.

provider "aws" {
  region = var.region

  default_tags {
    tags = {
      Project = "pathways-mllp-only"
    }
  }
}

module "pathways" {
  source = "../.."

  name   = "mllp-only"
  vpc_id = var.vpc_id

  private_subnet_ids = var.private_subnet_ids

  # Who may connect to the MLLP listeners: the hospital system and the lab, each on its own network.
  allowed_cidr_blocks = concat(var.hospital_cidr_blocks, var.lab_cidr_blocks)

  image = var.image

  # One listener per channel's source; the network load balancer exists because there is at least
  # one. No http_sources, so no application load balancer and no certificate.
  mllp_sources = {
    adt     = { port = 2575 }
    results = { port = 2577 }
  }
  probe_port = 9091

  # Each destination's MLLP port on its own network, and HTTPS for the AWS APIs.
  egress_rules = {
    https = {
      port        = 443
      cidr_blocks = ["0.0.0.0/0"]
    }
    lab = {
      port        = 2576
      cidr_blocks = var.lab_cidr_blocks
    }
    ehr = {
      port        = 2578
      cidr_blocks = var.ehr_cidr_blocks
    }
  }

  environment = {
    PATHWAYS_STORAGE = "postgres"
  }
  secrets = {
    PATHWAYS_KEY_2026_11 = var.master_key_secret_arn
  }
}
```

### project/channels/adt-to-lab/channel.yaml

```yaml title="examples/mllp-only/project/channels/adt-to-lab/channel.yaml"
# One channel: take ADT over MLLP from the hospital system and send each admission on to the lab's
# MLLP receiver. The lab's address is a placeholder.
name: adt-to-lab
format: hl7v2

source:
  mllp:
    # mllp_sources.adt in the example's main.tf: the network load balancer passes this port through.
    port: 2575
    host: 0.0.0.0
    # The engine terminates TLS itself. Add the certificate and key to the image.
    tls:
      cert: ../../certs/server.pem
      key: ../../certs/server.key

transform: ./transform.ts

destinations:
  - mllp:
      # egress_rules.lab in the example's main.tf lets the engine reach this port.
      host: lab.example.com
      port: 2576
      tls:
        ca: ../../certs/lab-ca.pem
```

### project/channels/adt-to-lab/transform.ts

```ts title="examples/mllp-only/project/channels/adt-to-lab/transform.ts"
// Only admissions go to the lab, addressed to it in MSH-5. Every other message is filtered out.
import type { Transform } from "@cosyte/pathways";

export default ((msg) => {
  if (!msg.is("ADT^A01")) return null;
  msg.setField("MSH.5", "LAB");
  return msg;
}) satisfies Transform;
```

### project/pathways.yaml

```yaml title="examples/mllp-only/project/pathways.yaml"
# The Pathways project this example deploys: copy it into a project `pathways init` made, build the
# project's image (its Dockerfile names the Pathways image by digest) and pass that image's digest as
# the example's image variable. Every value the module sets reaches the engine as an environment
# variable this file reads with { env: NAME }.

storage:
  kind: { env: PATHWAYS_STORAGE, default: sqlite }
  postgres:
    # The module writes the database's URL to a secret ECS injects as PATHWAYS_DATABASE_URL.
    url: { env: PATHWAYS_DATABASE_URL }
    # The RDS global bundle, https://truststore.pki.rds.amazonaws.com/global/global-bundle.pem, added
    # to the image: the database refuses connections without TLS.
    tls: { ca: certs/rds-global-bundle.pem }

encryption:
  # 32 random bytes in base64, in a Secrets Manager secret the example passes as secrets.
  keys: [{ id: "2026-11", env: PATHWAYS_KEY_2026_11 }]
  current: "2026-11"

# The load balancer checks /readyz here, and ECS runs `pathways probe` against /livez. host:
# 0.0.0.0 lets them reach it; it carries no message.
probes:
  port: 9091
  host: 0.0.0.0
  plaintext: true
```
