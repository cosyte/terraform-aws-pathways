# The sftp-and-bucket example

`examples/sftp-and-bucket` exchanges files only: partners use SFTP, and the engine reads and writes
the S3 bucket behind it.

## What it deploys

In an existing VPC, with a NAT gateway you already have:

- **One engine** on ECS Fargate, 1 vCPU and 2 GiB, and the migrate task definition.
- **PostgreSQL on RDS**, `db.t4g.medium`, Multi-AZ, deletion protection on.
- **An S3 bucket**, encrypted under the module's key, versioned, private and TLS only, with its access
  log bucket. Its lifecycle rules remove noncurrent versions after 30 days, unfinished uploads after
  7, and what the clinic has not picked up after 30.
- **An SFTP server**, internal, open on port 22 to the partners' networks alone, with two users on
  SSH keys: `lab`, whose home is `partners/lab`, and `clinic`, whose home is `partners/clinic`.
- **No load balancer**: with no MLLP or HTTP source the module creates neither.
- **The KMS key**, the database's secret, the log groups, the security groups and the roles.
- **The channel** in `project/`: each result the lab uploads to `/inbox` is copied to the clinic's
  `/outbox`. Its source lists the prefix every 30 seconds.

## When to choose it

When partners send and pick up files rather than holding a connection open.

## What it does not cover

- SFTP from the internet: the endpoint is internal, reached over your VPN or another private link.
- Passwords: users sign in with SSH keys only.
- MLLP or HTTP sources: see [complete](./example-complete.md).

## What it costs to leave running

We give what bills, not prices: AWS sets those per region and changes them. Price each line in the
[AWS Pricing Calculator](https://calculator.aws/) for your region.

| What | How it bills while it runs |
| --- | --- |
| The SFTP server | per hour the SFTP protocol is enabled, whether or not anyone connects, and per GB transferred |
| The engine, Fargate, 1 vCPU and 2 GiB | per second the task runs, all month |
| The database, `db.t4g.medium`, Multi-AZ | per hour of the instance, twice over for the standby, all month |
| Database storage, 50 GiB to start | per GB-month allocated, twice over with Multi-AZ, and backups beyond the database's size |
| The bucket and its log bucket | per GB-month stored, noncurrent versions included, and per request: the source lists its prefix every 30 seconds, all month |
| The KMS key and the database's secret | per month each, and per request or call |
| CloudWatch Logs | per GB ingested, and per GB-month kept for `log_retention_days` (365) |
| Your NAT gateway, already there | per GB the tasks send through it |

The SFTP server's hourly charge is often the largest line of a small deployment like this one.

### README.md

```md title="examples/sftp-and-bucket/README.md"
# sftp-and-bucket

Files only: partners exchange files over SFTP, and the engine reads and writes them in the S3 bucket
behind it. No load balancer.

## What it builds

In an existing VPC, with a NAT gateway you already have:

- one engine on ECS Fargate, 1 vCPU and 2 GiB, and the migrate task definition;
- PostgreSQL on RDS, Multi-AZ, `db.t4g.medium`, with deletion protection on (the module's defaults);
- an S3 bucket, encrypted under the module's key with an S3 Bucket Key, versioned, all public access
  blocked, TLS only, with its access log bucket. Its lifecycle rules remove noncurrent versions after
  30 days, unfinished uploads after 7, and what the clinic has not picked up after 30;
- an SFTP server on an internal VPC endpoint, open on port 22 to the partners' networks alone, with
  two users on SSH keys: `lab`, whose home is `partners/lab`, and `clinic`, whose home is
  `partners/clinic`. Each sees its home as `/` and reaches nothing outside it;
- no load balancer: with no MLLP or HTTP source the module creates neither;
- the KMS key, the secret, the log groups (the SFTP server's included), the security groups and the
  roles;
- the one channel in [`project/`](project): each result the lab uploads to `/inbox` is copied to the
  clinic's `/outbox`.

## When to choose it

When your partners send and pick up files rather than holding a connection open: batch results,
claims, rosters, or anything a partner already sends over SFTP. The engine needs no access key: its
task role reaches the bucket.

## What it costs

We give what bills, not prices: AWS sets those per region and changes them.

- The SFTP server per hour for the SFTP protocol, from creation until deletion, whether or not anyone
  connects, and per GB uploaded and downloaded. For a small deployment this is often the largest
  line.
- Fargate, per second, for 1 vCPU and 2 GiB, all month.
- The database instance per hour, twice over for Multi-AZ; storage per GB-month, twice over.
- S3 per GB-month stored, noncurrent versions included until the lifecycle rules remove them, and per
  request. The file source lists its prefix every `pollInterval` (30 seconds here), so its list
  requests run all month even when no file arrives. The access logs are objects in the log bucket.
- The KMS key, the secret, and CloudWatch Logs per GB ingested and stored.
- Your NAT gateway, per GB the tasks send through it.

## What it does not cover

- SFTP from the internet: the endpoint is internal, so partners reach it over your VPN or another
  private link. An internet-facing endpoint needs Elastic IPs, which the module does not create yet.
- Passwords: users sign in with SSH keys only.
- MLLP or HTTP sources: add `mllp_sources` or `http_sources`, as
  [`complete`](../complete) does.
- Telling a partner a file arrived: the partner polls its outbox.

## Use it

Every value in [`variables.tf`](variables.tf) is a placeholder. Copy `project/` into a project
`pathways init` made, add the RDS global bundle under `certs/`, build the image and push it, set the
variables and the partners' SSH public keys, then plan and apply from your own pipeline with your own
credentials. CI here validates this directory and tests it against mocked providers
(`tests/example-sftp-and-bucket`); nothing in this repository applies it.
```

### main.tf

```hcl title="examples/sftp-and-bucket/main.tf"
# Files only: partners exchange files over SFTP, and the engine reads and writes them in the S3
# bucket behind it. No MLLP or HTTP source, so no load balancer exists. Two partners, each locked to
# its own prefix: the lab uploads results to its inbox, and the clinic picks up its copies from its
# outbox. The one channel in project/ moves each result from the lab's inbox to the clinic's outbox.
#
# Every value here is a placeholder: the VPC and subnet ids, the account id 123456789012, the image
# digest, the secret ARN and the SSH keys. Put your own in before you plan.

provider "aws" {
  region = var.region

  default_tags {
    tags = {
      Project = "pathways-files"
    }
  }
}

module "pathways" {
  source = "../.."

  name   = "files"
  vpc_id = var.vpc_id

  private_subnet_ids = var.private_subnet_ids

  # No load balancer exists without a source of its kind, so this opens nothing; the module asks for
  # it all the same. SFTP has its own list below.
  allowed_cidr_blocks = var.sftp_allowed_cidr_blocks

  image = var.image

  # No MLLP or HTTP source: the channel reads files. The probe listener is still there for ECS.
  mllp_sources = {}
  http_sources = {}
  probe_port   = 9091

  environment = {
    PATHWAYS_STORAGE = "postgres"
  }
  secrets = {
    PATHWAYS_KEY_2026_11 = var.master_key_secret_arn
  }

  # The bucket. The engine gets its name as PATHWAYS_BUCKET, and its task role may use it.
  bucket_enabled = true
  bucket_lifecycle_rules = {
    default = {
      noncurrent_version_expiration_days     = 30
      abort_incomplete_multipart_upload_days = 7
    }
    # What the clinic has not picked up in 30 days goes.
    clinic_outbox = {
      prefix          = "partners/clinic/outbox/"
      expiration_days = 30
    }
  }

  # SFTP for both partners, from their networks only, each in its own home.
  sftp_enabled             = true
  sftp_allowed_cidr_blocks = var.sftp_allowed_cidr_blocks
  sftp_users = {
    lab = {
      public_keys = [var.lab_public_key]
      home_prefix = "partners/lab"
    }
    clinic = {
      public_keys = [var.clinic_public_key]
      home_prefix = "partners/clinic"
    }
  }
}
```

### project/channels/lab-results-in/channel.yaml

```yaml title="examples/sftp-and-bucket/project/channels/lab-results-in/channel.yaml"
# One channel: read each result file the lab uploads over SFTP to its inbox, and write a copy to the
# clinic's outbox, where the clinic picks it up over SFTP. Both are prefixes of the module's bucket:
# the lab's SFTP home is partners/lab, so it uploads to /inbox, and the clinic's is partners/clinic,
# so it sees the copies under /outbox.
name: lab-results-in
format: hl7v2

source:
  file:
    dir: partners/lab/inbox
    # A file younger than this may still be uploading, and is left for a later pass.
    minAge: 5s
    # Each pass lists the prefix: every 30 seconds keeps the list requests few.
    pollInterval: 30s
    s3:
      # The module sets PATHWAYS_BUCKET to its bucket's name. The engine's task role may use the
      # bucket, and the AWS SDK finds that role and the region on its own: no credential here.
      bucket: { env: PATHWAYS_BUCKET }

destinations:
  - file:
      dir: partners/clinic/outbox
      s3:
        bucket: { env: PATHWAYS_BUCKET }
```

### project/pathways.yaml

```yaml title="examples/sftp-and-bucket/project/pathways.yaml"
# The Pathways project this example deploys: copy it into a project `pathways init` made, build the
# project's image (its Dockerfile names the Pathways image by digest) and pass that image's digest as
# the example's image variable. Every value the module sets reaches the engine as an environment
# variable this file reads with { env: NAME }.

storage:
  kind: { env: PATHWAYS_STORAGE, default: sqlite }
  postgres:
    # The module writes the database's URL to a secret ECS injects as PATHWAYS_DATABASE_URL.
    url: { env: PATHWAYS_DATABASE_URL }
    # The RDS global bundle, https://truststore.pki.rds.amazonaws.com/global/global-bundle.pem, added
    # to the image: the database refuses connections without TLS.
    tls: { ca: certs/rds-global-bundle.pem }

encryption:
  # 32 random bytes in base64, in a Secrets Manager secret the example passes as secrets.
  keys: [{ id: "2026-11", env: PATHWAYS_KEY_2026_11 }]
  current: "2026-11"

# The load balancer checks /readyz here, and ECS runs `pathways probe` against /livez. host:
# 0.0.0.0 lets them reach it; it carries no message.
probes:
  port: 9091
  host: 0.0.0.0
  plaintext: true
```
