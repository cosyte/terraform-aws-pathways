# The bring-your-own-vpc example

`examples/bring-your-own-vpc` finds a VPC and its subnets by their tags, and creates no network.

## What it deploys

It reads the VPC tagged `Name = integration-vpc` and its subnets tagged `Tier = app`, `data` and
`edge`, and builds in them:

- **One engine** on ECS Fargate, 1 vCPU and 2 GiB, in the `app` subnets.
- **PostgreSQL on RDS**, `db.t4g.medium`, Multi-AZ, in the `data` subnets (`database_subnet_ids`).
- **A network load balancer**, internal, with one MLLP listener, in the `edge` subnets
  (`load_balancer_subnet_ids`).
- **The KMS key**, the database's secret, the log groups, the security groups and the roles.
- **The channel** in `project/`: ADT over MLLP in, admissions over MLLP out to the lab.

The subnet ids are sorted, so the order AWS returns them in does not change the plan.

## When to choose it

When a platform team owns the VPC, its routes, its NAT gateway and its peering, and hands you subnets
by tag.

## What it does not cover

- Creating a VPC, a subnet, a route table or a NAT gateway: neither the module nor this example does.
- Subnets in one availability zone: the module refuses fewer than two subnets per tier, but cannot
  tell two in the same zone apart.
- Network ACLs and firewall routes, which your network team keeps.

## What it costs to leave running

We give what bills, not prices: AWS sets those per region and changes them. Price each line in the
[AWS Pricing Calculator](https://calculator.aws/) for your region.

| What | How it bills while it runs |
| --- | --- |
| The engine, Fargate, 1 vCPU and 2 GiB | per second the task runs, all month |
| The database, `db.t4g.medium`, Multi-AZ | per hour of the instance, twice over for the standby, all month |
| Database storage, 50 GiB to start | per GB-month allocated, twice over with Multi-AZ, and backups beyond the database's size |
| The network load balancer | per hour it exists, and per capacity unit used |
| The KMS key and the database's secret | per month each, and per request or call |
| CloudWatch Logs | per GB ingested, and per GB-month kept for `log_retention_days` (365) |
| The VPC's NAT gateway, your network team's | per GB the tasks send through it |

### README.md

```md title="examples/bring-your-own-vpc/README.md"
# bring-your-own-vpc

Pathways in a VPC your network team already runs, found by its tags, with each tier in its own
subnets.

## What it builds

It reads, and creates none of: the VPC tagged `Name = integration-vpc`, and its subnets tagged
`Tier = app`, `data` and `edge`. In them it builds:

- one engine on ECS Fargate, 1 vCPU and 2 GiB (the module's default), in the `app` subnets;
- PostgreSQL on RDS, Multi-AZ, `db.t4g.medium`, in the `data` subnets (`database_subnet_ids`);
- an internal network load balancer with one MLLP listener, in the `edge` subnets
  (`load_balancer_subnet_ids`);
- the KMS key, the secret, the log groups, the security groups and the roles;
- the one channel in [`project/`](project): ADT over MLLP in, admissions over MLLP out to the lab.

## When to choose it

When the network is not yours to change: a platform team owns the VPC, its routes, its NAT gateway
and its peering, and hands you subnets by tag. Looking them up by tag means a subnet replaced by
that team is picked up on your next plan, with no id to edit.

## What it costs

We give what bills, not prices: AWS sets those per region and changes them.

- Fargate, per second, for 1 vCPU and 2 GiB, all month.
- The database instance per hour, twice over for Multi-AZ; storage per GB-month, twice over; backups
  beyond the database's size.
- The network load balancer per hour and per capacity unit.
- The KMS key, the secret, and CloudWatch Logs per GB ingested and stored.
- The VPC's NAT gateway and its data transfer, which your network team's bill already carries.

## What it does not cover

- Creating the network. The module and this example never create a VPC, a subnet, a route table or
  a NAT gateway. A VPC with no NAT gateway: see [`private-only`](../private-only).
- A tag that matches no subnet, or subnets in one availability zone: the module refuses fewer than
  two subnets for each tier, but cannot tell two subnets in the same zone apart. Tag subnets in two
  zones or more.
- Rules your network team keeps elsewhere, such as network ACLs and firewall routes: open port 2575
  from your senders to the `edge` subnets, and 2576 from the `app` subnets to the lab.

## Use it

Set `vpc_name` and the three tier tags to your own, and the other placeholders in
[`variables.tf`](variables.tf). Copy `project/` into a project `pathways init` made, add the RDS
global bundle, the MLLP source's certificate and key and the lab's CA under `certs/`, build the image
and push it, then plan and apply from your own pipeline with your own credentials. CI here validates
this directory and tests it against mocked providers (`tests/example-bring-your-own-vpc`); nothing
in this repository applies it.
```

### main.tf

```hcl title="examples/bring-your-own-vpc/main.tf"
# Pathways in a VPC your network team already runs, found by its tags rather than by ids pasted in,
# with each tier in its own subnets: the engine in the private application subnets, the database in
# the database subnets, and the internal load balancer in the subnets your network routes partner
# traffic to. This example creates no network: no VPC, no subnet, no route and no NAT gateway.
#
# The tags are placeholders for your own: a VPC tagged Name = var.vpc_name, and subnets in it tagged
# Tier = app, data and edge. Every other value is a placeholder too: the account id 123456789012,
# the image digest and the secret ARN.

provider "aws" {
  region = var.region

  default_tags {
    tags = {
      Project = "pathways-byo-vpc"
    }
  }
}

data "aws_vpc" "this" {
  tags = {
    Name = var.vpc_name
  }
}

data "aws_subnets" "app" {
  filter {
    name   = "vpc-id"
    values = [data.aws_vpc.this.id]
  }
  tags = {
    Tier = var.app_subnet_tier
  }
}

data "aws_subnets" "data" {
  filter {
    name   = "vpc-id"
    values = [data.aws_vpc.this.id]
  }
  tags = {
    Tier = var.data_subnet_tier
  }
}

data "aws_subnets" "edge" {
  filter {
    name   = "vpc-id"
    values = [data.aws_vpc.this.id]
  }
  tags = {
    Tier = var.edge_subnet_tier
  }
}

module "pathways" {
  source = "../.."

  name   = "byo-vpc"
  vpc_id = data.aws_vpc.this.id

  # Each tier in its own subnets. Sorted, so the order AWS returns them in does not change the plan.
  private_subnet_ids       = sort(data.aws_subnets.app.ids)
  database_subnet_ids      = sort(data.aws_subnets.data.ids)
  load_balancer_subnet_ids = sort(data.aws_subnets.edge.ids)

  # The load balancer stays internal (the module's default): your network brings partners to it.
  load_balancer_internal = true
  allowed_cidr_blocks    = var.allowed_cidr_blocks

  image = var.image

  mllp_sources = {
    adt = { port = 2575 }
  }
  probe_port = 9091

  egress_rules = {
    https = {
      port        = 443
      cidr_blocks = ["0.0.0.0/0"]
    }
    lab = {
      port        = 2576
      cidr_blocks = var.lab_cidr_blocks
    }
  }

  environment = {
    PATHWAYS_STORAGE = "postgres"
  }
  secrets = {
    PATHWAYS_KEY_2026_11 = var.master_key_secret_arn
  }
}
```

### project/channels/adt-to-lab/channel.yaml

```yaml title="examples/bring-your-own-vpc/project/channels/adt-to-lab/channel.yaml"
# One channel: take ADT over MLLP from the hospital system and send each admission on to the lab's
# MLLP receiver. The lab's address is a placeholder.
name: adt-to-lab
format: hl7v2

source:
  mllp:
    # mllp_sources.adt in the example's main.tf: the network load balancer passes this port through.
    port: 2575
    host: 0.0.0.0
    # The engine terminates TLS itself. Add the certificate and key to the image.
    tls:
      cert: ../../certs/server.pem
      key: ../../certs/server.key

transform: ./transform.ts

destinations:
  - mllp:
      # egress_rules.lab in the example's main.tf lets the engine reach this port.
      host: lab.example.com
      port: 2576
      tls:
        ca: ../../certs/lab-ca.pem
```

### project/channels/adt-to-lab/transform.ts

```ts title="examples/bring-your-own-vpc/project/channels/adt-to-lab/transform.ts"
// Only admissions go to the lab, addressed to it in MSH-5. Every other message is filtered out.
import type { Transform } from "@cosyte/pathways";

export default ((msg) => {
  if (!msg.is("ADT^A01")) return null;
  msg.setField("MSH.5", "LAB");
  return msg;
}) satisfies Transform;
```

### project/pathways.yaml

```yaml title="examples/bring-your-own-vpc/project/pathways.yaml"
# The Pathways project this example deploys: copy it into a project `pathways init` made, build the
# project's image (its Dockerfile names the Pathways image by digest) and pass that image's digest as
# the example's image variable. Every value the module sets reaches the engine as an environment
# variable this file reads with { env: NAME }.

storage:
  kind: { env: PATHWAYS_STORAGE, default: sqlite }
  postgres:
    # The module writes the database's URL to a secret ECS injects as PATHWAYS_DATABASE_URL.
    url: { env: PATHWAYS_DATABASE_URL }
    # The RDS global bundle, https://truststore.pki.rds.amazonaws.com/global/global-bundle.pem, added
    # to the image: the database refuses connections without TLS.
    tls: { ca: certs/rds-global-bundle.pem }

encryption:
  # 32 random bytes in base64, in a Secrets Manager secret the example passes as secrets.
  keys: [{ id: "2026-11", env: PATHWAYS_KEY_2026_11 }]
  current: "2026-11"

# The load balancer checks /readyz here, and ECS runs `pathways probe` against /livez. host:
# 0.0.0.0 lets them reach it; it carries no message.
probes:
  port: 9091
  host: 0.0.0.0
  plaintext: true
```
