# alarms

CloudWatch alarms on four of the metrics Pathways serves at `/metrics` on its health endpoint, and
what it takes to read them on Fargate. The root module calls it when `alarms_enabled` is true, and
then adds the collector container to the engine's task through the ecs submodule.

- **A health token**: a Secrets Manager secret, encrypted under the key you give, holding a bearer
  token the module generates. The token is generated by an ephemeral resource and written in a
  write-only argument, so neither the plan nor the state holds it. ECS injects it into the engine
  as `PATHWAYS_HEALTH_TOKEN`, which the health endpoint reads by default, and into the collector, so
  `/metrics` stays authenticated. Raise `health_token_version` to write a new one, then force a new
  deployment of the service.
- **The collector's configuration** (`collector_config`), for an OpenTelemetry collector beside the
  engine: it scrapes `http://127.0.0.1:<health_port>/metrics` every 30 seconds inside the task,
  keeps only the four families below (of the settlements, only those that failed), folds away their
  channel, destination and outcome labels, and writes them as CloudWatch embedded metric format
  lines to the metrics log group. No channel or destination name leaves the task.
- **The metrics log group**, `<log_group_prefix>/metrics`, encrypted under the key, with a
  retention. The task role gets `logs:CreateLogStream` and `logs:PutLogEvents` on it, and nothing
  else.
- **Four alarms** in the `Pathways` namespace, each on the dimension `Deployment = <name>`, each
  publishing to `sns_topic_arn` on alarm and on OK:

| Alarm                | Metric                                                | Fires when                                                                        |
| -------------------- | ----------------------------------------------------- | --------------------------------------------------------------------------------- |
| `store-down`         | `pathways_store_up`, minimum                          | below 1, or missing, for `store_down_minutes` minutes (2)                         |
| `oldest-pending-age` | `pathways_oldest_pending_age_seconds`, maximum        | above `oldest_pending_age_seconds` (600) for 5 minutes                            |
| `refused-messages`   | `pathways_messages_refused_total`, sum                | more than `refused_messages_threshold` (0) in 15 minutes                          |
| `settled-failed`     | `pathways_settled_destinations_total` (failed), sum   | more than `settled_failed_threshold` (0) in 15 minutes                            |

The two counters reach CloudWatch as what was added since the previous scrape, so a sum over a
period is how many in that period.

```hcl
module "pathways_alarms" {
  source = "github.com/cosyte/terraform-aws-pathways//modules/alarms"

  name             = "integration"
  log_group_prefix = "/pathways/integration"
  kms_key_arn      = module.pathways_kms.key_arn
  task_role_name   = module.pathways_iam.task_role_name
  sns_topic_arn    = "arn:aws:sns:us-east-1:123456789012:pathways-alarms"
}
```

It has no provider block: your `aws` provider and its region apply. Inputs are in
[`variables.tf`](variables.tf), outputs in [`outputs.tf`](outputs.tf).
